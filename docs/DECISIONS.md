# 設計判断記録

Codexは重要な判断を追記する。既存項目を無言で書き換えず、日付、判断、理由、影響を記録する。

## D-001: GoでTUIアプリとして実装する

- 状態: 採用
- 理由: チャプターの複数選択、選択変更時の経過時間再計算、永続キュー、即時プロセス中断があり、単純なシェル対話より状態管理とテストが必要。

## D-002: エンコード境界はチャプター番号だけを使う

- 状態: 採用・変更禁止
- 理由: 秒数指定ではミリ秒単位の欠けが大量に発生するため。

## D-003: キュー先頭を成功まで残す

- 状態: 採用
- 理由: 中断、エラー、クラッシュ後に同じジョブをそのまま再実行でき、running状態の復旧処理が不要。

## D-004: キュー編集UIは作らない

- 状態: 初期版対象外
- 理由: 実装・保守コストが大きい。事故時はアプリ停止後に整形済み`queue.json`を裏技的に編集できる。

## D-005: 出力先は設定ファイルに一項目だけ持つ

- 状態: D-026で置き換え
- 既定値: `/Volumes/2TB HDD/mp4/`
- 理由: 毎回選択する必要がなく、初期版の設定画面も不要。

## D-006: ファイル選択は簡素にする

- 状態: 固定名前順についてはD-029で更新。検索・選択式ソートを作らない判断は継続
- 理由: 容量表示、子移動、親移動だけで足りる。検索、ソート、チャプター事前取得は保守コストに見合わない。

## D-007: Goバージョン

- 状態: 採用
- 内容: Go 1.26系、ローカルで利用可能な最新パッチ版。
- 理由: 2026-07-23時点の現行安定系列を使い、標準ライブラリの現行機能を利用する。


## D-008: 製品実装前に実エンコードPoCを必須化する

- 状態: 採用・変更禁止
- 内容: `docs/POC_RESULT.md`が`GO`になるまで製品コードを作らない。
- 理由: HandBrakeCLIのチャプター、音声、字幕、プリセット、停止挙動が実装後に想定と異なると、アーキテクチャ全体の手戻りが大きいため。
- 検証: 短いMKVの実エンコード、ffprobe、デコード後フレームハッシュ、Goからのシグナル停止を使う。

## D-009: プロジェクト名をChapterBrakeとする

- 状態: 採用
- 内容: リポジトリ名と実行コマンドは`chapterbrake`、ランタイムデータは`~/Documents/ChapterBrake/`。
- 理由: HandBrakeを使ったチャプター単位の分割・キュー実行ツールであることが短く分かるため。

## D-010: DLNA表示用タイトルを出力ファイル名へ統一する

- 状態: 採用・必須
- 内容: 各ジョブのタイトルメタデータは、最終出力ファイル名から拡張子を除いた値とする。
- 理由: HandBrake出力直後は元タイトルが引き継がれ、DLNAサーバー・クライアントで連番ファイル名ではなく元メタデータが表示される実運用上の問題があるため。

## D-011: MKVはmkvpropedit、MP4はffmpegストリームコピーでタイトル設定する

- 状態: 採用、PoCで最終確認
- 内容: MKVは`mkvpropedit`でセグメントタイトルだけを直接変更する。MP4はffmpegの`-c copy`による再多重化でタイトルを設定する。
- 理由: MKVはファイル全体の再多重化を避け、映像・音声タイムスタンプを触らず高速に処理できる。MP4には同等の直接編集手段を前提とせず、既存の動作実績があるFFmpeg方式を使う。どちらも再エンコードしない。

## D-012: タイトル処理完了まで最終ファイル名を公開しない

- 状態: 採用
- 内容: HandBrakeCLIは隠し一時ファイルへ出力し、タイトル設定と検証後に最終名へrenameする。
- 理由: DLNAサーバーがタイトル修正前のファイルを取り込み、古いメタデータをキャッシュすることと、不完全ファイルを完成品として見せることを防ぐため。

## D-013: Milestone 0をNO-GOで停止する

- 日付: 2026-07-26
- 状態: 採用・実装禁止
- 内容: HandBrakeCLI 1.11.2の`--chapters`で非先頭チャプターを指定すると、選択開始前の映像30フレームが混入した。3秒チャプターと30秒チャプターで再現したため、現要件のままMilestone 1へ進まない。
- 理由: エンコード境界はチャプター番号だけを使い、境界の欠落・重複を許さないことが絶対条件である。時刻、フレーム、PTS指定による補正は要件違反となる。
- 影響: `docs/POC_RESULT.md`を`NO-GO`とし、`cmd/`、`internal/`、本番`go.mod`を作成しない。

## D-014: MP4 title処理では全ストリームmapを使わない

- 日付: 2026-07-26
- 状態: PoCで確認、NO-GO解消後の実装候補
- 内容: HandBrake MP4に対する`-map 0 -map_chapters 0`はチャプター用`bin_data`を重複させる。映像・音声を明示mapし、チャプターは`-map_chapters 0`で一度だけ生成する。
- 引数: `-map 0:v -map 0:a? -map_metadata 0 -map_chapters 0 -c copy -brand <入力major_brand>`
- 検証: 修正後はストリーム数、チャプター、タイムスタンプ、映像・音声パケットハッシュが一致した。

## D-015: 外部コマンド中断はプロセスグループSIGINTを第一段階にする

- 日付: 2026-07-26
- 状態: PoCで確認、NO-GO解消後の実装候補
- 内容: macOSで外部コマンドを新規プロセスグループとして起動し、SIGINT、期限後SIGKILL、Wait、部分出力削除の順にする。
- 検証: HandBrakeCLI、ffmpeg、mkvpropeditがSIGKILLなしで停止し、グループ残留がなく、Wait後に部分出力を削除できた。

## D-016: TUI候補をtviewとする

- 日付: 2026-07-26
- 状態: PoC候補、製品採用は保留
- 内容: tview v0.42.0でList、Checkbox、InputField、Pages、Ctrl+C捕捉が最小コードで成立した。
- 理由: 初期版に必要なウィジェットが直接提供され、画面要件に対する独自実装量が少ない。
- 影響: P-03のNO-GOが解消した場合に、保守状況と最新版を再確認して採用を確定する。

## D-018: HandBrake GUI相当のチャプター境界挙動を許容する

- 日付: 2026-07-26
- 状態: 採用
- 内容: チャプター範囲は引き続きHandBrakeCLIのチャプター番号だけで指定する。同じ素材・プリセット・範囲をHandBrake GUIで処理した場合と同等の素材依存の境界重複・欠落はHandBrakeの仕様として許容する。
- 補正: 秒・フレーム・PTSによる範囲補正、固定フレーム数の除去、エンコード後の自動トリミングは行わない。
- 理由: 従来のGUI運用でも同じ挙動で実害がなく、素材依存の境界を自動補正すると正常フレームや音声・字幕同期を損なう可能性があるため。
- 影響: D-013のP-03による実装禁止理由を解消し、P-03を合格へ変更する。完成アプリの実利用で問題が確認された場合だけ別要件として再検討する。

## D-020: 音声は高品質・標準品質の2版をプリセットから生成する

- 日付: 2026-07-26
- 状態: 採用・PoCで確認
- 内容: 利用者による任意ビットレート入力を廃止する。入力音声トラック1・2から
  1本以上を選択し、各入力からプリセット由来の高品質・標準品質を同じ出力へ格納する。
- 高品質: プリセットのパススルー音声ルール。入力非対応時はスキャン結果に基づき、
  プリセットのフォールバックエンコーダと高品質ルールの設定を明示する。
- 標準品質: プリセットの非パススルー音声ルール。
- UI: 入力トラックの使用チェックだけを持ち、ビットレート数値欄は作らない。
- プリセット制約: パススルー1件、非パススルー1件、必要なフォールバックを
  一意に解決できないプリセットはキュー追加前に拒否する。
- 検証: 入力1のみ、2のみ、1+2、パススルー非対応AAC入力、MP4プリセットで、
  高品質・標準品質が欠落せず期待順に生成された。

この判断はD-022で置き換えた。

## D-022: 内蔵プリセットと音声方針をHandBrake GUIから分離する

- 日付: 2026-07-26
- 状態: 採用
- 判断: 既定一覧はGUI `My Presets`の設定ファイルを読むのではなく、
  ChapterBrake内蔵の`1080p MP4`、`1080p MKV`、`480p MP4`とする。
  「その他」ではHandBrakeCLIの標準プリセットを表示する。
- 音声: 映像プリセットの音声ルールへ依存せず、高品質は可能ならパススルー、
  非対応時はAAC 640 kbps・5.1ch、標準品質はAAC 160 kbps・stereoとする。
- 内蔵対応: `1080p MP4`は`Super HQ 1080p30 Surround`、`1080p MKV`は
  `H.264 MKV 1080p30`、`480p MP4`は`Fast 480p30`を土台とする。
  コンテナをCLIで後から変更せず、元から同じコンテナの標準プリセットを使う。
- 安全境界: 初期版でパススルーするのは実エンコード済みのAC-3だけとし、
  その他の入力コーデックは高品質AACへフォールバックする。
- 理由: GUIの`My Presets`は選択体験の参考であり、GUIへの実行時依存要件ではない。
  既存カスタムプリセットで重要なのは解像度とMP4/MKVで、その他は標準
  プリセットのコピーを土台としていたため。

内蔵プリセット数とクロップ差の判断はD-025で置き換えた。GUI非依存と音声方針は
引き続き有効とする。

## D-024: MP4のチャプター用dataストリームではlanguageタグを構造比較しない

- 日付: 2026-07-26
- 状態: 採用・実ツール統合試験で確認
- 内容: MP4 title後処理の前後比較では、映像・音声・字幕のコーデック、順序、
  時刻、チャンネル、言語と、dataストリームのコーデック・時刻を比較する。
  チャプター用`bin_data`のlanguageタグだけは比較しない。
- 理由: PoC確定済みのffmpeg引数でも`bin_data`のlanguageが`und`から`eng`へ
  変わるが、チャプター数・時刻・名称、映像・音声内容には変化がないため。

## D-025: GUI相当の内蔵プリセット4件とクロップ差を維持する

- 日付: 2026-07-26
- 状態: 採用・実機設定で再確認
- 内容: GUIのMy Presetsに対応する`MP4 Presets`、`MKV Presets`、
  `My Old Presets`、`GCCX`の4件をChapterBrake内蔵一覧へ表示する。
- 低解像度: `My Old Presets`は480p MP4・自動クロップ、`GCCX`は
  480p MP4・クロップなしとする。前者へ`--crop-mode auto`、後者へ
  `--crop-mode none`を明示する。
- 互換性: 修正前のChapterBrakeが保存した`1080p MP4`、`1080p MKV`、
  `480p MP4`というキュー名も対応する内蔵設定へ解決する。
- 標準一覧: HandBrakeCLI 1.11.2では`--preset-list`の一覧がstderrへ出るため、
  stdoutだけでなくstderrも取得して解析する。
- 理由: 解像度とコンテナが同じ低解像度2件を重複と判断したのは誤りであり、
  GUI実設定には自動クロップの有無という意図的な差が存在したため。

## D-026: 既定入力先を設定に持ち、`--cwd`で一時上書きする

- 日付: 2026-07-26
- 状態: D-027で置き換え
- 内容: `settings.json`へ`input_directory`を追加し、既定値を
  `/Volumes/2TB HDD/Images`とする。引数なしではこの設定からファイル選択を
  開始し、`--cwd`付きではその一回だけカレントディレクトリから開始する。
- 永続化: `--cwd`は設定を書き換えない。恒久的な変更は、アプリ停止中に
  `input_directory`を編集する。
- 互換性: version 1の設定は既存`output_directory`を維持し、既定入力先を
  追加してversion 2へ原子的に移行する。不正JSONと未知versionは従来どおり
  fail closedとする。
- 理由: 通常の入力場所は固定して起動操作を短くしつつ、一時的に別の場所を
  扱う場合は設定変更と戻し忘れを避けられる。

## D-027: ディレクトリ指定オプションで入力先を一時上書きする

- 日付: 2026-07-26
- 状態: 採用
- 内容: `--cwd`を廃止し、`--directory PATH`と短縮形`-d PATH`を提供する。
  指定パスは絶対パスへ解決し、存在するディレクトリであることを検証してから
  ファイル選択を開始する。
- 使用例: カレントディレクトリは`chapterbrake -d .`、任意のディレクトリは
  `chapterbrake --directory /path/to/videos`とする。
- 永続化: コマンドライン指定はその一回だけ有効で、`settings.json`を変更しない。
- 理由: カレントディレクトリ専用フラグよりも、同じ一つの操作で任意の一時入力先を
  指定できるほうが単純で汎用的である。

## D-028: チャプター区切り時間を設定とジョブ追加画面で変更可能にする

- 日付: 2026-07-26
- 状態: 採用
- 設定: `settings.json`へ`chapter_interval`を正の`分:秒`文字列として追加し、
  既定値を`23:40`とする。分は59を超えてよく、秒は2桁の`00`から`59`とする。
- 画面: チャプター分割画面の先頭で区切り時間を編集できる。入力欄のEnterまたは
  近似選択ボタンで再計算する。画面変更はそのジョブ追加フローだけに適用し、
  設定ファイルへ書き戻さない。
- 再計算: 時間を変更して次へ進んだ場合は、手動選択済みチャプターを破棄し、
  新しい時間による近似開始位置を選択し直す。
- 永続化: キューへは従来どおり確定したチャプター番号範囲だけを保存し、補助値である
  区切り時間をジョブへ重複保存しない。
- 互換性: version 1・2の既知設定は既存値を維持し、既定区切り時間を追加して
  version 3へ原子的に移行する。不正値と未知versionはfail closedとする。
- 理由: 通常値は毎回入力せずに済み、素材ごとの例外だけを、結果を確認する
  チャプター分割画面で変更できる。

## D-029: ファイル選択一覧を固定の名前昇順にする

- 日付: 2026-07-26
- 状態: 採用
- 内容: 親ディレクトリ`../`は先頭へ固定し、それ以外の表示対象はディレクトリと
  MKVを区別せず、大文字小文字を区別しない名前昇順で表示する。同一視される名前は
  元の文字列で順序を決める。
- 対象外: 利用者が切り替えるソート方式や、更新日時・容量によるソートは追加しない。
- 理由: OSのディレクトリエントリ列挙順は利用者にとって予測しづらく、固定の名前順
  なら毎回同じ位置から目的の入力を探せる。
