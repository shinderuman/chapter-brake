# 実装開始前PoCゲート

## 1. 目的

製品実装を進めた後で、HandBrakeCLIやタイトルメタデータ後処理の制約により根本設計が成立しないと判明することを防ぐ。

このPoCは「コマンドが存在する」「ヘルプにオプションがある」の確認ではなく、**実際に短いMKVをエンコードし、出力を機械的に検証して、現在の要求が実現可能であることを証明する工程**である。

## 2. 絶対ルール

- `docs/POC_RESULT.md`が最終的に`GO`となるまで製品コードを作らない。
- `GO WITH CHANGES`は未完了。設計変更後に影響試験を再実行する。
- 必須項目の未確認、手確認だけ、推測は合格としない。
- PoC用コードは`poc/`へ隔離する。`cmd/`、`internal/`、本番`go.mod`は作らない。
- PoC用の最小Goプログラムは、プロセス起動・中断の成立性確認に限る。アプリ設計を先行実装しない。
- 失敗を回避するため要件を無言で弱めない。設計変更は`docs/DECISIONS.md`へ記録する。

## 3. 検証素材

可能な限り、短く再生成可能なMKVを作る。巨大な実利用ファイルをPoCの必須前提にしない。

検証素材には最低限次を含める。

- 4個以上のチャプター
- 既知のチャプター開始時刻
- 2本の識別可能な音声トラック
- 少なくとも1本、可能なら2本の字幕トラック
- 字幕表示時間が明確な区間
- チャプターごとに開始映像を識別できる要素

ffmpegだけで生成できない要素がある場合は、利用可能なmkvmerge等を使ってよい。使用コマンドを保存し、再生成可能にする。

GUIカスタムプリセット確認など、生成素材だけでは確認できない項目には、ローカルの代表的な実利用MKVを追加で使ってよい。

## 4. 必須試験

### P-01 環境と能力確認

- HandBrakeCLI、ffprobe、ffmpeg、mkvpropeditの実行ファイルとバージョンを記録する。
- `HandBrakeCLI --help`の実環境オプションを保存する。
- GUIカスタムプリセットを含む一覧取得方法を確認する。
- プリセットのコンテナを名前推測なしで判定できる経路を確認する。
- MP4/MKVプリセットを実際に一回ずつ使い、生成コンテナをffprobeで確認する。

合格条件: プログラムから再現可能な取得・判定手順が確定している。

### P-02 入力解析と番号対応

- チャプター、音声、字幕を機械可読形式で取得する。
- ffprobe等の番号とHandBrakeCLIが受け取るトラック番号の対応を実エンコードで確定する。
- 入力音声1と2、字幕1以降を誤認しないことを確認する。

合格条件: 解析結果からHandBrakeCLI引数へ変換する規則が曖昧でない。

### P-03 チャプター範囲だけによる切り出し

- `start-at`、`stop-at`、秒数、PTSを一切使わない。
- 先頭チャプターを含む範囲と、先頭以外から始まる範囲を試す。
- 例として`1:2`、`3:4`、単一チャプターなど複数パターンを実エンコードする。
- 実行引数を記録する。
- 出力の開始内容、終了内容、再生時間、チャプター情報をffprobe等で確認する。
- 連続範囲を別ファイルへ分割し、各区間の期待時間と出力時間をソースのtime baseに基づいて比較する。
- 複数出力の合計で、反復する説明不能な欠落または重複がないことを確認する。

許容差は映像フレーム・音声フレーム・コンテナtime baseを考慮して根拠付きで定める。単なる「数秒以内」は不可。

合格条件: チャプター番号だけで要求どおりの連続分割を安全に実装できる。

### P-04 音声トラック選択とビットレート

次を個別に実エンコードする。

1. 入力トラック1のみ、640 kbps
2. 入力トラック2のみ、640 kbps
3. 入力トラック1と2、順に640/160 kbps

各出力について次を検証する。

- 出力音声トラック数
- 入力との対応
- 並び順
- コーデック
- ビットレート
- HandBrakeログ上の選択内容

ffprobeでbit_rateを取得できない形式では、HandBrakeログ、パケット統計、MediaInfo等の代替検証を記録する。

合格条件: 初期版で正式サポートする1/2トラックの全パターンを一意に生成できる。

### P-05 字幕のソフト格納と非焼き付け証明

MKVで次を作る。

1. 字幕なし
2. 字幕トラック1をソフト字幕として格納
3. 複数字幕がある場合は複数格納

ffprobeで字幕ストリームの有無・数・形式を確認する。

字幕が焼き付いていないことは、字幕表示中の同一時刻について「字幕なし出力」と「ソフト字幕出力」のデコード後映像フレームハッシュを比較して確認する。同一映像設定でフレームハッシュが一致することを証拠とする。ビットストリームハッシュではなくデコード後フレームを比較する。

MP4でも字幕なし出力を作り、同様に焼き付けがないことを確認する。

格納不能字幕をHandBrakeが自動的に焼き付ける場合は不合格。自動フォールバックを拒否できる経路を確定するまで実装禁止。

合格条件: 字幕選択がソフト字幕または完全な字幕なしとなり、映像焼き付けが発生しない。

### P-06 タイトルメタデータ後処理

DLNA表示名の実績要件として、最終出力ファイルのtitleをファイル名のstemへ設定する。

MKV:

- HandBrake出力の一時MKVへmkvpropeditでtitleを設定する。
- ffprobe等で設定値を確認する。
- 後処理前後で映像・音声・字幕のストリーム数、コーデック、チャプター、duration、time baseを比較する。
- デコード後の映像フレームハッシュと音声ハッシュまたは同等の検証で、内容が変化していないことを確認する。
- 数GiBの実利用ファイルでもファイル全体の再多重化を行わず短時間で完了することを確認する。
- 失敗または中断時のファイル状態を確認する。

MP4:

- HandBrake出力の一時MP4から、ffmpegのストリームコピーで別の一時MP4を作りtitleを設定する。
- 全ストリーム、メタデータ、チャプターを保持する正確な引数を確定する。
- ffprobeでtitle、ストリーム数、コーデック、チャプター、duration、start_time、time baseを比較する。
- デコード後の映像フレームハッシュと音声ハッシュまたは同等の検証で再エンコード・品質変化がないことを確認する。
- 音声開始時刻、各ストリームduration、A/V同期に説明不能な変化がないことを確認する。

共通:

- 出力stemに日本語、空白、記号があるケースを試す。
- タイトル設定と検証後に同一ディレクトリ内のrenameで最終名へ公開できることを確認する。
- 実際のDLNAサーバー・クライアントで、MKVとMP4がファイル名のstemで表示されることを代表例で確認する。DLNA側のキャッシュ更新手順も記録する。

合格条件: MKVは再多重化なし、MP4は再エンコードなしで、内容・同期・必要なストリームを維持しながらtitleを確実に設定できる。

### P-07 既存出力と部分出力

- 既存出力に対するHandBrakeCLIの挙動を確認する。
- アプリ側で開始前に削除する方針が安全に成立することを確認する。
- 削除不能時にHandBrakeCLIを起動しない設計が可能であることを確認する。

この項目はHandBrakeCLIの自動上書き機能に依存しない。

### P-08 Goからの即時中断

`poc/`に最小Goスパイクを作り、実際のHandBrakeCLIを起動する。十分に長く動く入力・設定を使う。

確認項目:

- TUI操作相当のキャンセル要求からHandBrakeCLI、ffmpeg、mkvpropeditの各段階を停止できる。
- SIGINT、SIGTERM、期限後SIGKILLのどの手順を使うべきか確定する。
- 必要ならプロセスグループへシグナルを送れる。
- 各外部コマンドの子プロセスが残らない。
- 終了状態を通常失敗と区別できる。
- プロセス終了を待ってから部分出力を削除できる。
- 部分出力削除後、同じジョブを最初から再実行できる。
- 中断開始から終了までの実測時間を記録する。

合格条件: アプリが実行中ジョブを即時中断し、後始末できる具体的なGo実装経路が確定している。

### P-09 ログと進捗

- stdoutとstderrを欠落なくファイルへ保存する。
- 同時にTUI用進捗を取得できるか確認する。
- JSON進捗が使えない場合は、壊れやすい全文パースを避けた代替を決める。進捗を詳細表示できなくても、ログ完全保存ができればこの項目は条件付き合格とできる。
- 大量出力をメモリへ全保持しない方法を確認する。

合格条件: 完全ログを失わず、最低限の進行状態を表示できる。

### P-10 最小TUIライブラリの成立確認

- 現在保守されている候補を比較する。
- チェックリスト、リスト選択、テキスト入力、画面遷移、即時キャンセルを過剰な独自実装なしで行えるか、小さな使い捨てスパイクで確認する。
- 検索、ソート、高度なファイラー機能は試作しない。

この試験はHandBrake統合より低リスクだが、採用依存を実装開始前に確定する。

## 5. 証拠として残すもの

- 実行した全主要コマンド
- HandBrakeCLIの完全な引数配列
- 入力素材生成手順
- ffprobe JSONまたは同等の機械可読結果
- フレームハッシュ比較結果
- 音声トラック・ビットレート検証結果
- MKV/MP4のタイトル設定前後比較とDLNA表示確認
- シグナル送信、終了コード、停止所要時間、残留プロセス確認
- HandBrakeCLI、mkvpropedit、ffmpeg、ffprobeのstdout/stderrログのパス
- 失敗した試行と、その原因

## 6. 判定

### GO

すべての必須項目が合格し、製品実装で使う具体的なコマンド・番号対応・停止手順が確定している。

### GO WITH CHANGES

要求は実現可能だが設計変更が必要。変更を仕様書へ反映し、影響試験を再実行する。最終判定がGOになるまで製品実装禁止。

### NO-GO

必須要求が実現不能、安全に検証不能、または保守可能な方法がない。製品実装禁止。

## 7. PoC完了後

`docs/POC_RESULT_TEMPLATE.md`を複製して`docs/POC_RESULT.md`を作成する。GO判定でも、その時点では実装へ進まず、利用者へ結果を報告して停止する。
